# mkos-schemas changelog

The Python package `mkos-schemas` and the npm package `@maniacultasset/schemas` (installed by the FE
as `"@mkos/schemas": "npm:@maniacultasset/schemas@<version>"`) share one version, released by one
`schemas-v<version>` tag.

**Version rule after a tag.** Any PR that changes the contract (`jsonschema/**`, `ts/src/**`, the
`mkos_schemas` models, or `openapi.json` through the API registry) once `schemas-v<current>` exists:

- If this file has an open `## 1.N.0 (unreleased)` heading, add the entry under it.
- Otherwise bump to the next MINOR in one commit: `packages/schemas/pyproject.toml`,
  `packages/schemas/ts/package.json`, `SCHEMA_VERSION` in `src/mkos_schemas/base.py`, every fixture's
  `schema_version`, and the regenerated outputs; then open `## 1.N.0 (unreleased)`.
- A description-only change may take a PATCH instead, unless a MINOR heading is already open.
- Classify each change first (docs/RULES.md §11): adding a member to a closed vocabulary (an error
  code to a declared set included) is MAJOR and waits for its window.
- The tagging PR closes the heading (`## 1.N.0 (YYYY-MM-DD)`). The publish workflow refuses a tag
  whose heading is still `(unreleased)`, and `make contracts` refuses contract changes at an
  already tagged version (`scripts/ci/schemas_version_check.sh`).

## 2.1.0 (unreleased)

- Sign in and sign up with Google (ADR-0020, proposed; additive MINOR after 2.0.0: new operations and models, three optional response fields, no new error code, no new member in any closed vocabulary; `SignInStatus` and `AuthMethod` are unchanged). Tech Lead approval 2026-10-30; the AI and FE leads are unnamed, so the Tech Lead approved alone. **Operations: 65 -> 72.** Google only proves who the person is: every Google sign-in still goes through the Kuinn code (or the enrolment) under `MFA_ENFORCEMENT=all`, and a token's `amr` lists only Kuinn's own factors (`otp`, `rc`; never `pwd` for a Google session). With `GOOGLE_OAUTH_ENABLED=false` (the default) `start` redirects (302) to `/login?error=google_unavailable`, the callback 303 `/auth/google?error=unavailable`, and the JSON steps 501 `NOT_IMPLEMENTED`.
  - `auth_google_config` (GET `/auth/google/config`, public): 200 `GoogleConfigOut {enabled}`, the flag. Show "Continue with Google" only when `enabled`.
  - `auth_google_start` (GET `/auth/google/start?b=`, public, 302 to Google): `b` is base64url(sha256(UTF-8 bytes of the secret's 43-character base64url text)), never the hash of the 32 raw bytes; the browser keeps the secret in sessionStorage. One endpoint for the login and the sign-up page; the page choice stays client-side. Only the app's own page navigation may start it: a request whose `Sec-Fetch-Site` is not `same-origin`, or whose `Sec-Fetch-Mode` is not `navigate`, gets 302 `/auth/google?error=failed` and nothing is stored.
  - `auth_google_callback` (GET `/auth/google/callback`, public, 303): the OAuth client's redirect URI, `{DASHBOARD_BASE_URL}/api/v1/auth/google/callback`. It redirects to the app route `/auth/google?handle=<opaque>` (60 s, single use, bound to the browser) or `?error=cancelled|failed|unavailable`.
  - `auth_google_complete` (POST `/auth/google/complete`, public): `GoogleCompleteRequest {handle, binding}` -> 200 `GoogleCompleteOut {outcome, email, login, signup, details, link}` (`email`: Google's verified email, on every outcome) with exactly the outcome's field set: `sign_in` -> `login` (`LoginResult`: tokens, or a challenge for the usual `/auth/login/mfa`, `/auth/login/mfa/enroll|confirm` or `/auth/password/expired` step), `pending` -> `signup` (`SignupStatusOut`), `needs_details` -> `details` (`GoogleDetailsOut {email, email_verified: true, owner_name, given_name, family_name, suggested_brand_name, details_handle, details_expires_in}`), `link_required` -> `link` (`GoogleLinkOut {email, link_handle, link_expires_in}`). 401 `OAUTH_STATE_INVALID` for an unknown, used, expired or foreign handle; 401 `UNAUTHENTICATED` (one generic message) for every refusal.
  - `auth_google_link` (POST `/auth/google/link`, public): `GoogleLinkRequest {link_handle, binding, password}` -> 200 `LoginResult`. The existing account's password, then its code: Google is linked only when that sign-in finishes. A wrong password counts toward the lockout and is the login's 401; the handle stays usable for 15 minutes.
  - `auth_google_unlink` (POST `/auth/google/unlink`, bearer, step-up `any`, 204): removes the linked Google account; 422 `VALIDATION_FAILED` while the account has no password.
  - `signup_google` (POST `/signup/google`, public, 202): `GoogleSignupRequest {details_handle, binding, brand_name, owner_name, phone?, website?}` -> `SignupStatusOut` (pending). A platform admin still approves (ADR-0019).
  - `SecurityOut` gains `has_password` and `google_linked` (optional booleans); `SignupRequestOut` gains `verified_via` (`"google"` or null).
  - **FE:** add `/auth/google/complete`, `/auth/google/link` and `/signup/google` to the exact-match public no-refresh paths; keep handles and the challenge token in memory only; resume the existing MFA steps from `login`; hide "Change password" when `has_password` is false; show "Verified by Google" on `verified_via`.
  - **AI:** no change.

## 1.0.0

First contract release. It ships outside the 4 Oct window as a one-time exception: nothing is pinned to 0.0.0. Later breaking changes wait for 18 Oct or 1 Nov.

Adding a member to a closed vocabulary (an enum, a `Literal`, a `RuleDef` union, or a path) is a breaking change.

- Requires Python `==3.13.*` and `pydantic>=2.11,<3`.
- `ImportReport` uses `import_id`, not `batch_id`.
- `ErrorCode` has 76 members. The 11 API codes added for the `/api/v1` surface (S3): `UNAUTHENTICATED`, `PERMISSION_DENIED`, `NOT_FOUND`, `METHOD_NOT_ALLOWED`, `IDEMPOTENCY_KEY_REUSED`, `STALE_VERSION`, `PAYLOAD_TOO_LARGE`, `NOT_IMPLEMENTED`, `OAUTH_STATE_INVALID`, `LAST_OWNER_REQUIRED` and `MARKETPLACE_ACCOUNT_CONFLICT`. None has an `ErrorClass`; `NOT_IMPLEMENTED` is `system_failure`, the rest `user_action`.
- Frozen status vocabularies: `ListingStatus` (9), `ListingResult.status` (3), `MarketplaceState` (8), `JobState` (7).
- `ImageRef` refuses `packaging_label` on a publishable listing. `ImageReport` may still name that slot.
- `GenerationContext.product` stays a dict through v1; the `facts.py` retype moves to after v1.
- New generated outputs (S3): `jsonschema/openapi.json` (the frozen `/api/v1` surface: 35 operations at S3, one error envelope, keyset pages) and the TypeScript types `ts/src/{api.d.ts,contracts.d.ts,index.ts}`, published as `@maniacultasset/schemas` (FE alias `@mkos/schemas`).
- Products (S12; still 1.0.0 because `schemas-v1.0.0` is not tagged yet): `POST /api/v1/products`, `GET /api/v1/products` and `GET /api/v1/products/{product_id}` go live. `ProductCreate.category` and `ProductOut.category` are now **required** slugs (the user decided this on 2026-10-06, TEAM-QUESTIONS T115; `products.category` is NOT NULL).
