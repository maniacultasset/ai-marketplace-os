# Ready-to-delegate gate

When every line is true, the foundation is done and feature tickets can be handed to other developers. Until then they will be blocked and asking us questions.

- [ ] ONBOARDING PROVES ITSELF: on a machine that has never seen the repo, `git clone && cp .env.example .env && make dev` boots postgres+redis+minio, applies migrations, seeds two tenants, serves /docs and runs an arq worker in under 10 minutes with zero questions asked. Verified by a second person, not by the author.
- [ ] CI IS REAL AND BLOCKING: a dummy PR runs api-lint, api-typecheck, api-tests, tenant-isolation, schemas-drift, contracts, commit-lint, web-lint and web-typecheck as separate named jobs; branch protection on main enforces them plus CODEOWNERS review, linear history and squash-only, with administrators included; a force-push to main is rejected for an org admin.
- [ ] CONTRACTS FROZEN AND TAGGED: mkos-schemas v1.0.0 is tagged and installable; all eight contracts (CanonicalListing, ErrorReport, ImageReport, AgentRunRecord, ValidationResult, JobEnvelope, GenerationResult, ListingResult) have golden fixtures that round-trip; the generated JSON Schema and TypeScript files are committed; the schemas-drift job fails on a hand-edited generated file.
- [ ] API SURFACE PUBLISHED: every planned /api/v1 endpoint exists as a stub with the correct response_model; openapi.json is committed and regenerates identically in CI; apps/web/src/lib/api-types.ts is generated from it; `make mock` serves prism on :4010; the FE team has confirmed in writing that they import the generated types and hand-write no response interfaces.
- [ ] MIGRATIONS ARE REPRODUCIBLE AND REVERSIBLE: 0000 through 0004 apply cleanly to both a throwaway pgvector:pg16 container and staging Cloud SQL; `alembic upgrade head` → `downgrade base` → `upgrade head` round-trips green in CI (the downgrade is the test people skip, and the first prod rollback on Day 44 is the wrong time to find migration 0004 has no downgrade); `alembic check` is a required check and fails on model/head drift.
- [ ] TENANT ISOLATION IS MECHANICALLY ENFORCED: tenant_id is NOT NULL and indexed on all twelve tenant-owned tables, held by composite FKs; the cross-tenant test covers relational reads AND pgvector similarity search, loops over every TenantScoped mapper, runs as its own required CI job, and demonstrably FAILS when the tenant filter is removed; a raw unscoped `select(Listing)` raises CrossTenantQueryError.
- [ ] SEED AND FIXTURES ARE THE SHARED GROUND TRUTH: `make seed` creates two tenants with deliberately overlapping SKUs and at least one user per role per tenant, works with NO LLM key and NO GCP credentials, and exports packages/schemas/fixtures/*.json that the FE and AI teams both use.
- [ ] AUTH AND MAKER-CHECKER WORK AT BOTH LEVELS: login issues a JWT carrying the frozen claim set; a reviewer-only token gets 403 on POST /listings/generate; refresh rotation revokes the whole chain on reuse; a generator approving their own listing is rejected with a well-formed 403 ErrorReport at the API AND by the DB trigger when the API is bypassed; `UPDATE audit_log` fails for app_rw; the permission matrix is in the FE and AI teams' hands.
- [ ] WALKING SKELETON IS LIVE: api-staging and web-staging run on Cloud Run over Google-managed TLS on the client's domain, reading secrets from Secret Manager, deployed automatically on push to main with the migration running as a Cloud Run job BEFORE the deploy; a second person logs in and creates a product end-to-end.
- [ ] ONE REAL ASYNC JOB RUNS END TO END: a 50-row CSV with 5 malformed rows returns 45 imported products and 5 row-level errors (never a batch crash); re-uploading the same file creates no duplicate SKUs; `GET /api/v1/jobs/{job_id}` returns the frozen JobEnvelope read from Postgres with Redis stopped; a forced terminal failure produces a DEAD_LETTER row, and requeue creates a NEW job row linked by parent_job_id.
- [ ] CORRELATION CHAIN IS UNBROKEN: a request carrying `X-Request-ID: abc` shows that id in the response header, every backend log line, the enqueued ARQ payload, the worker's log lines, the job_runs row and the agent_runs row; structlog emits Cloud Logging JSON; a log line containing a fake marketplace secret comes out redacted; /healthz and /readyz are wired to the Cloud Run probes.
- [ ] THE AI SEAM IS EXERCISED BEFORE THE AI TEAM ARRIVES: PipelineDeps Protocol, a stub `run_listing_pipeline`, FakeAdapter and `record_agent_run` are merged; a developer with no GCP credentials and no LLM key can run the generation job end-to-end against fakes; the import-linter contract forbidding `packages.pipeline -> apps.api` and the ruff rule forbidding openai imports inside app/services/ both fail a deliberately bad PR.
- [ ] WE CAN SEE OUR OWN RESULTS: /internal/admin renders tenants, products, listings, listing_versions, agent_runs, job_runs and audit_log read-only behind GCP IAM with token_enc and hashed_password excluded (asserted by a unit test); the four ops pages (/queue, /cost, /funnel, /dlq) render from SQL; a CI test proves /internal/admin and /docs return 404 when ENV=production.
- [ ] DECISIONS ARE WRITTEN DOWN, NOT REMEMBERED: ADRs 0001–0008 merged (GCP-not-AWS, uv+3.11+monorepo, JWT issuer, /api/v1, tenant_id denormalisation, CanonicalListing nested, AI seam in-process, pgvector HNSW+1536); ONBOARDING.md covers the 10 invariants, the repo tour, GCP access and the ticket flow; the DB contract note, the JWT claim contract, the RBAC matrix and the frozen node-event name strings have been SENT to the AI and FE teams in writing, not just committed.
- [ ] EXTERNAL CLOCK IS RUNNING: both marketplace developer applications are filed with reference numbers recorded in the risk register; GCP billing is verified; the OpenAI key is in Secret Manager with the tier prepay made; the domain resolves; the client has named the two launch categories and the two UAT humans.
