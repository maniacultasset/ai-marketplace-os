# THE CANON

THE CANON is the single authoritative register for AI Marketplace OS. Where any section of the kickoff pack, any build-step (S1–S14), any code block, any .env draft or any spec document disagrees with a row in this document, THE CANON wins and the other text is superseded on sight — no discussion, no Slack thread, no "but my section says". It exists because seven sections were drafted in parallel and never reconciled, producing 19 CRITICAL collisions on exactly the four contracts three teams consume (API prefix, the shared schemas package, the AI seam, the job table). Every row below is a decision, not a recommendation: a developer starting Monday resolves any conflict here and nowhere else, and a change to any row requires a PR against this file with 2 approvals (Tech Lead + the owning team) before any code moves.

> Where any document, code block, spec or draft disagrees with a row below, **the Canon wins.**

## The AI seam

The single interface the AI team implements. Nothing else crosses this boundary.


**Module:** `Implementation: packages/pipeline/src/mkos_pipeline/graph.py, re-exported from packages/pipeline/src/mkos_pipeline/__init__.py — the backend generation worker calls `from mkos_pipeline import run_listing_pipeline`. Contract (the Protocol, the signature and every type it names): packages/schemas/src/mkos_schemas/pipeline.py. packages/pipeline is a uv workspace member (dist mkos-pipeline, import mkos_pipeline) and depends only on mkos-schemas + langgraph/langchain-core/openai/tiktoken.`


```python
async def run_listing_pipeline(ctx: GenerationContext, deps: PipelineDeps) -> GenerationResult
```


**Who persists `agent_runs`:** The BACKEND generation worker, and only the backend generation worker. The AI team appends AgentRunRecord objects to GenerationResult.agent_runs[] and returns them; the worker INSERTs them alongside the listing_version, validation_runs and the job_runs status update in ONE transaction. `PipelineDeps.record_agent_run` is DELETED from the Protocol. `mkos_schemas/telemetry.py` and its record_agent_run context manager are DELETED from packages/schemas (which stays pydantic-only, single dependency pydantic>=2.9,<3) and move to apps/api/app/services/telemetry.py, where the backend uses them for its OWN model calls (embeddings and vision), which never pass through the seam. Rule of thumb: whoever executes the model call owns the row — the AI team executes generation/correction calls and returns records, the backend executes embedding/vision calls and writes records directly. Exactly one row per model call, no double counting.


**Rules:**

- Context is PUSHED, not pulled. GenerationContext carries everything knowable up front — product, brand_profile, marketplace_rules (now typed RuleSet), category_template (now typed CategoryTemplate), previous_version, user_instructions, max_attempts, plus request_id/job_id/tenant_id/product_id/listing_id/marketplace/category. The backend assembles it before enqueue; the AI package fetches nothing.
- PipelineDeps is FROZEN at exactly five ports, all implemented by the backend: `async retrieve_brand_chunks(tenant_id: UUID, query: str, k: int = 8, types: Sequence[str] | None = None) -> Sequence[BrandChunkDTO]`; `async validate_rules(listing: CanonicalListing) -> ErrorReport`; `async validate_images(listing: CanonicalListing) -> list[ImageReport]`; `async get_model_credentials(purpose: Literal['generation','vision','embedding']) -> ModelCredentials`; `async emit_node_event(node: PipelineStage, status: Literal['started','ok','failed'], detail: dict | None = None) -> None`.
- DELETED from PipelineDeps: `load_rules` and `load_category_template` (now pushed in ctx), `validate_schema` (it is `CanonicalListing.model_validate` — pure pydantic, no port needed), and `record_agent_run` (see the persistence rule above).
- AgentState is NOT part of the contract. It is AI-team-internal LangGraph state, never crosses the seam, and is removed from every 'frozen contract' list, from packages/schemas and from the function signature. Nobody outside packages/pipeline may import it.
- Four types are ADDED to packages/schemas before the schemas-v1.0.0 tag, all WireModel: `BrandChunkDTO` (id, tenant_id, type, text, similarity, source_type, source_id, chunk_index) — a plain DTO, never app.models.BrandChunk, because the AI package may not import SQLAlchemy; `RuleSet` (marketplace, category, version, rules: list[Rule] where Rule = field_path, kind, params, severity, message, code); `CategoryTemplate` (marketplace, category, external_category_id, required_attributes, optional_attributes); `ModelCredentials` (provider, api_key, api_base, model, timeout_seconds).
- GenerationResult is the ONLY return value. terminal_state is one of generated | needs_review | blocked | failed; blocks[] carries per-agent partial success; attempts_used reflects the in-graph correction cap of 3.
- The graph has NO publish node and NO approval node. It terminates at quality_check. Publish authority belongs to POST /api/v1/listings/publish and the publish worker, after asserting status='approved'. Spec [16]'s node table listing await_approval and publish is WRONG and is superseded here.
- The AI package imports no sqlalchemy, no FastAPI, no app.*, opens no DB session, reads no os.environ, and never sees marketplace_accounts or any OAuth token. Enforced by an import-linter forbidden contract (packages.pipeline -> apps.api) plus GCP IAM: the AI team's Google group holds no secretAccessor on AMAZON_* / FLIPKART_*.
- The ruff banned-api rule on `openai` and `langgraph` is scoped, not global: per-file-ignores for TID251 in packages/pipeline/** plus a narrow exemption for apps/api/app/services/embeddings.py and apps/api/app/services/vision.py, which are the backend's only sanctioned model-calling modules. app/services/rules_engine.py stays hard-banned — that is how 'rules are data, not code' becomes mechanically true.
- mypy strict applies to packages/schemas and apps/api. packages/pipeline runs mypy in non-strict mode (no disallow_untyped_defs) for the sprint; the seam function and everything in mkos_schemas stay fully typed. Agreed with the AI team in writing before Day 11.
- The backend ships a FakeAdapter and a stub `run_listing_pipeline` that returns a valid GenerationResult from fixtures on Day 5, so the seam is executable and the generation worker is testable before the AI team writes a single node.
- Ownership line: BACKEND owns brand-document chunking, embedding calls, the deterministic Pillow image checks and BrandChunkRepository.search. AI owns all generation and correction prompts plus the vision prompt content, exposed to them through deps.validate_images. This line is repeated verbatim in ONBOARDING.md.
- Change control: this seam is frozen Fri 25 Sep 2026 (Day 5). Any change is a PR against THE CANON plus a MINOR/MAJOR bump of mkos-schemas, needing approval from Tech Lead + AI lead + FE lead. MINOR = additive optional field, any day. MAJOR = rename/removal/type change, only in the Day-14 / Day-28 / Day-42 windows.
